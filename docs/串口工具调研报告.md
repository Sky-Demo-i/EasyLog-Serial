# 串口工具调研报告：给 EasyLogger 配一个顺手的上位机

> 调研时间：2026-10-28　｜　场景假设：嵌入式设备通过 UART 输出 EasyLogger 日志，PC 侧需要一款串口工具来查看、过滤、记录这些日志，同时兼顾协议调试
> 说明：GitHub 星标数为当日 API 查询值；免费/收费策略和版本可能变化，落地前请以官网为准。

## 一、结论先行

| 你的主要诉求 | 首选 | 备选 | 说明 |
| --- | --- | --- | --- |
| **看 EasyLogger 日志**（高亮、长日志、跨平台） | **comNG** | Tera Term、Termite | comNG 是目前最接近"日志查看器"的串口工具 |
| **看带颜色的日志**（ANSI） | **Tera Term** | PuTTY、PlatformIO Serial Monitor | 只有终端模拟器会真正渲染颜色 |
| **调协议、发 HEX、快速验证** | **SSCOM**（Windows） | XCOM、Hercules、RealTerm | 国产万金油，单文件免安装 |
| **跨平台 / 开源可改** | **COMTool** | SerialTest | 都是开源，可做二次开发 |
| **看传感器数据、画曲线** | **Serial Studio** | SerialTest、野火多功能调试助手 | 免费版已覆盖串口 + 仪表盘 |
| **旁路监听别人发的数据** | **Eltima Serial Port Monitor** | AccessPort、com0com + 双开 | 不占用端口，抓真实通信 |
| **不想离开编辑器** | **VS Code Serial Monitor** | PlatformIO 内置监视器 | 轻量，功能基础 |

**一句话结论**：现成工具里，没有一款"懂 EasyLogger"——它们要么是字节收发器（SSCOM/XCOM），要么是通用终端（Tera Term/PuTTY），要么是数据仪表盘（Serial Studio）。**最接近的是 comNG 的语法高亮 + 条件中断**。如果你的目标是做一款"EasyLog 官方配套上位机"，市场是存在空白的。

## 二、EasyLogger 对串口工具的特殊要求

EasyLogger（[armink/EasyLogger](https://github.com/armink/EasyLogger)，MIT，4.8k★）不是普通的 `printf`，它有几个特性会直接影响工具选型：

1. **有结构的文本**
   一行日志包含级别（A/E/W/I/D/V）、tag、时间戳、函数名/行号等字段，字段可通过 `elog_set_fmt()` 裁剪。工具如果能解析这些字段，就能做"只看 ERROR""只看某个 tag"这类语义过滤；否则只能正则硬匹配。

2. **可选的 ANSI 颜色**
   `elog_set_text_color_enabled(true)` 打开后，输出里会混入 `\033[31m` 这类转义序列。**大多数国产串口助手按纯文本显示，会把这些序列显示成 `←[31m` 之类的乱码**，这是实际使用中最常见的第一个坑。

3. **hexdump / 异步输出 / 缓冲**
   `elog_hexdump()` 输出多行十六进制；异步模式（`ELOG_ASYNC_OUTPUT_ENABLE`）会把日志放进缓冲区由后台线程刷出，短时间可能出现突发流量。

4. **输出后端可换**
   串口只是其中一种后端，还支持文件、Flash（EasyFlash）等。所以配套工具最好只负责"串口这一端"，不要把解析逻辑写死。

**因此，"配套工具"其实是三类需求的合集**：看日志（Log Viewer）、调协议（Terminal）、看数据（Plotter）。市面上的工具通常只擅长其中一类。

## 四、市场地图

### 4.1 国产通用串口助手（Windows 为主）

**SSCOM（5.13.1）** —— 国内使用年限最久、兼容性最好的"万金油"。
- 优点：单文件绿色免安装、体积小、启动快；HEX/ASCII 双向、时间戳、定时发送、多条发送、文件收发、CRC 校验、TCP/UDP 二合一、可开多个实例。
- 缺点：界面老旧、按钮密集；**不支持 ANSI 颜色**；没有波形；长日志/高速率下接收区容易卡。
- 适合：现场快速验证、给甲方工程机临时用、老 USB 转串口兼容性排查。
- 来源：[大虾工作室官网](http://www.daxia.com/sscom/)

**XCOM（V2.6，正点原子）** —— 单片机入门事实标准。
- 优点：中文极简界面、免费、与正点原子开发板教程完全配套；多条发送、HEX、时间戳、数据保存齐全。
- 缺点：Windows-only；高级功能少；不支持 ANSI 颜色。
- 适合：STM32/51/ESP32 入门、课程设计、跟着教程走。

**友善串口调试助手** —— 老牌多串口工具。
- 优点：多串口、自动识别、自动收发保存、时间戳、收发字节统计。
- 缺点：界面传统，更新慢；无 ANSI/无色。
- 适合：需要同时盯多个串口的场合。

**Hercules SETUP utility（3.2.8）** —— 串口 + TCP Client/Server + UDP 四合一。
- 优点：免费、单 exe；能**假扮服务端**等设备连上来，这是多数调试助手没有的能力；HEX、宏、日志、Modem 信号控制齐全。
- 缺点：Windows-only；界面偏工业；商用分发要求在其网站放链接。
- 适合：设备主动上报、串口服务器、网络协议联调。
- 来源：[HW group 官网](https://www.hw-group.com/software/hercules-setup-utility)

**其他**：eCOM（老牌简单）、章鱼串口（数据采集/主题丰富）、串口猎人（带波形/协议分析）等，功能同质化严重，选一个顺手的即可，不必全部试。

### 4.2 终端模拟器（ANSI 颜色 + 日志的主场）

**Tera Term** —— Windows 上最推荐的"看彩色日志"工具。
- 优点：完整终端仿真，**正确渲染 ANSI 颜色**；可显式选择 CR/LF/CRLF；支持发送文件；自带 TTL 宏语言，可做自动化测试；日志记录完善；UTF-8 支持好。
- 缺点：不是 HEX 工具；界面偏传统；没有日志级别过滤。
- 适合：EasyLogger 开颜色时的第一选择；需要脚本化回归的场合。

**PuTTY** —— 极简、免费、跨平台。
- 优点：串口 + SSH/Telnet 一体，ANSI 颜色正常，日志可配。
- 缺点：**不能发 HEX**（敲 `AA 11` 发出去的是 8 个 ASCII 字符）；不能发文件；行尾控制弱。
- 适合：纯文本命令交互，不适合二进制协议。

**RealTerm** —— 为二进制和抓包而生。
- 优点：HEX 显示/发送、任意波特率、按帧同步、时间戳、Capture 到文件（可按大小/时间滚动、自动命名）、**Spy 模式可监听本机程序与串口之间的数据**、命令行/ActiveX 自动化。
- 缺点：界面极其老派、学习曲线陡；ANSI/VT100 模式可解析控制序列，但官方文档注明 VT100 不含颜色指令，**彩色支持有限**；ANSI 模式下不显示时间戳。
- 适合：Modbus/自定义二进制帧、长时间无人值守记录、排查"到底谁在发"。
- 来源：[RealTerm 官网](https://realterm.sourceforge.io/)

**Termite（3.4）** —— 极简文本终端 + 插件过滤器。
- 优点：极小（程序 76 KB）、免安装、可预置 INI 随产品分发；**插件机制**提供时间戳、HEX 视图、正则高亮、日志落盘、自动回复、功能键宏；可转发两个串口做监听。
- 缺点：只面向文本，不做二进制文件传输；**不渲染 ANSI 颜色**；无波形。
- 适合：把"给客户的小工具"预配置好直接发出去；想要极简但有高亮的场景。
- 来源：[CompuPhase 官网](https://www.compuphase.com/software_termite.htm)

**CoolTerm** —— macOS 上最好的选择，Windows/Linux 也有，HEX 收发、脚本、日志齐全。

### 4.3 日志 / 可视化新势力

**comNG** —— 本次调研中最贴合"看日志"定位的工具。
- 定位：不是"数据收发器"，而是"串口日志分析器"。
- 能力：
  - 多标签、多实例，可同时打开多个串口或日志文件；
  - **自研 comNGLang 语法高亮**：自动识别错误码、状态字等关键字段；
  - 类 Notepad++ 的 Style Token 自定义高亮，类 VS Code 的选中即高亮；
  - **Minimap 缩略图**，长日志快速定位；
  - **条件中断**：收到指定关键字（如 `ERROR`）自动关闭串口，防止刷屏淹没现场；
  - 日志签名：保存的日志可附加时间戳与操作者；
  - 通用图形化：特定格式数据自动画曲线；
  - HEX 模式、自定义波特率、流控、Modem 信号、时间戳、文件拖拽保存。
- 缺点：社区小（87★）；Electron 技术栈，安装包偏大；不懂 EasyLogger 的级别/tag 语义（靠语法高亮近似）；ANSI 渲染情况未确认。
- 许可：MIT，**可 fork/二次开发**。
- 来源：[GitHub](https://github.com/xenkuo/comNG)、[功能介绍](https://bbs.plcjs.com/thread-640337-1-4.html)

**Serial Studio（4.x）** —— 开源遥测仪表盘。
- 定位：把串口数据变成仪表盘/曲线，而不是看文本日志。
- 能力：串口/TCP/UDP/BLE；Plot、Bar、Gauge、Compass、GPS、Data Grid 等控件；JS/Lua 帧解析器；CSV 导出与回放；控制台模式也可纯看文本。
- 许可：核心 GPLv3；官方二进制免费版可个人/教育/开源使用，**商用需 Pro 或自行编译 GPL 版**；Pro 才有 Modbus/CAN/MQTT/OPC UA、3D/瀑布图、输出控件、多设备等。
- 缺点：不是为"读日志"设计的，文本检索/过滤弱；Pro 收费。
- 适合：传感器数据可视化、调试报告、教学演示。
- 来源：[Pro vs Free](https://serial-studio.com/help/pro-vs-free)、[GitHub](https://github.com/Serial-Studio/Serial-Studio)（7.3k★）

**COMTool** —— 跨平台、可插件化的串口/网络助手。
- 能力：Windows/macOS/Linux/树莓派；串口 + TCP/UDP；多串口；插件与二次开发；Python 技术栈。
- 许可：LGPL-3.0（核心改动需开源，插件可闭源）。
- 缺点：功能多、初次上手略复杂；Windows 稳定性口碑不如老牌工具。
- 适合：Linux/macOS 用户、想写插件扩展的团队。
- 来源：[GitHub](https://github.com/Neutree/COMTool)（2.6k★）

**SerialTest** —— Qt 写的跨平台收发 + 实时绘图 + 文件传输。
- 能力：Windows/Linux/macOS/Android；数据收发/监视、实时曲线、快捷发送、文件收发、Lua 脚本。
- 许可：GPL-3.0。
- 缺点：2024 年后更新趋缓；GPL 对商业闭源不友好。
- 来源：[GitHub](https://github.com/wh201906/SerialTest)（1.7k★）

| 工具 | 说明 |
| --- | --- |

### 4.5 开发环境内嵌

- **VS Code Serial Monitor**（Microsoft，免费，2.1M+ 安装）：在编辑器面板里直接收发文本，装完即用；功能基础（无 HEX、无高级过滤），胜在不用切窗口。
- **PlatformIO Serial Monitor**：嵌入式开发流里最顺手的方案；支持 ANSI 颜色、日志落盘、异常解码等过滤器；适合已经在用 PlatformIO 的团队。
- **logscope**（VS Code 扩展）：面向 Zephyr 日志的现代查看器，带过滤、搜索、按级别着色——代表"日志查看器插件化"的趋势，但目前偏 Zephyr 生态。
- **J-Link RTT Viewer**：不是串口，但如果你用的 MCU 支持 RTT，带宽和实时性远好于 UART，EasyLogger 也可以把输出端口换成 RTT。调试阶段值得常备。

## 六、针对 EasyLogger 的五个关键发现

### 1. ANSI 颜色是第一个坑，而且没有"既彩色又带时间戳"的完美方案

- EasyLogger 开颜色后输出 `ESC[31m...ESC[0m`，**SSCOM / XCOM / 友善 / Hercules / Termite 都会把它当普通字符显示**，看起来像乱码。
- 能正常渲染的是终端模拟器：Tera Term、PuTTY、minicom/picocom/tio、PlatformIO。
- RealTerm 虽有 ANSI/VT100 模式，但官方文档自己注明"VT100 不含颜色指令"，且 **ANSI 模式下不显示时间戳**。
- **最省事的做法**：调试期 `elog_set_text_color_enabled(false)`，用任意工具；或者只在 Tera Term 里开颜色，需要时间戳时再关。

### 2. 没有工具"认识"EasyLogger 的级别和 tag

- 现成工具的过滤基本是"关键字/正则"，没有"级别 ≥ WARN""tag 属于 {wifi, mqtt}"这种语义过滤。
- 最接近的是 **comNG 的语法高亮**（给 `ERROR`/`WARN` 配色）和 **Termite 的正则高亮插件**，但都只是"染色"，不是"过滤"。
- 这正是自研工具最有价值的功能点：**解析 + 结构化过滤 + 折叠**。

### 3. "能收"不等于"能长时间收"

- 921600 及以上波特率、或设备疯狂刷日志时，逐字节刷新文本控件的老工具会卡顿甚至丢数据。
- 相对稳的：RealTerm（Direct Capture）、comNG、Serial Studio、Tera Term（logging）、tio。
- 评估方法：让设备以 921600 连续发 10 分钟，看工具的行数统计和实际发送行数是否一致。

### 4. 时间戳有两套，必须区分

- 设备侧时间（EasyLogger 的 `elog_port_get_time()`，可能是开机时长或 RTC）和主机接收时间不是一回事。
- 排查"卡死/重启/看门狗"时，**行间 delta（距上一行多久）** 比绝对时间更有用。目前只有少数工具（如 comNG、tio）提供类似能力。

### 5. 免费工具的维护与许可风险

- SSCOM/XCOM/友善/AccessPort 都是闭源免费，遇到 bug 只能等作者；商用分发前最好确认许可。
- 开源里：comNG（MIT）最宽松，COMTool（LGPL）适合插件式扩展，SerialTest/Serial Studio 核心是 GPL，**闭源商业产品不能直接改**。

## 七、推荐组合

### 方案 A：个人 / 小团队，快速上手（零成本）

1. **comNG**：日常看日志、长日志定位、关键字断点。
2. **Tera Term**：需要 ANSI 彩色、或要发文件/写宏时用。
3. **SSCOM**：临时调协议、发 HEX、给现场工程机用。

### 方案 B：协议调试为主

1. **SSCOM**（文本/HEX/定时发送）
2. **RealTerm**（二进制帧、抓包、长时间 Capture）
3. **Hercules**（需要 TCP/UDP 或假扮服务端时）

### 方案 C：数据可视化 / 演示

1. **Serial Studio**（免费版）：仪表盘 + CSV。
2. **SerialTest** 或 **野火多功能调试助手**：实时曲线 / PID 调参。

### 方案 D：要做成"EasyLog 官方配套工具"

现成方案都不够贴合，建议**基于 comNG（MIT）fork** 或自研，见下一节。

## 八、如果自研：功能清单与技术选型

### 8.1 MVP（1～2 周可出可用版本）

1. **连接**：串口枚举、自定义波特率、8N1、DTR/RTS、自动重连（USB 拔插后 COM 号变化）。
2. **接收**：独立接收线程 + 环形缓冲，UI 只做批量刷新；支持 921600 不丢。
3. **解析**：可配置模板/正则，解析 `level / tag / time / file:line / message`；兼容 EasyLogger 默认格式与 `elog_set_fmt` 裁剪后的格式。
4. **颜色**：内置 ANSI SGR 解析（16 色 + 256 色），可一键"剥离 ANSI"。
5. **过滤**：级别阈值、tag 多选、关键字/正则、反向过滤；**过滤只影响显示，不影响落盘**。
6. **显示**：虚拟滚动（10 万行不卡）、暂停/冻结、搜索高亮、行号、delta 时间。
7. **记录**：原始字节 + 解析文本双写；按大小/时间滚动；可回放。
8. **发送**：多组命令、文本/HEX、行尾 CR/LF/CRLF、定时/循环发送。

### 8.2 P1（差异化）

- hexdump 折叠/展开（对应 `elog_hexdump`）
- 断线/重启检测（连续 N 秒无心跳或收到启动 banner 时提示）
- 统计面板：行/秒、字节/秒、各级别计数、错误 Top N tag
- 命令面板：把常用调试命令做成按钮/下拉，支持变量占位
- 会话文件格式（原始 + 解析 + 元数据），双击可回放

### 8.3 P2（加分项）

- 从日志里提取数值画曲线（`temp=25.3` → 实时曲线）
- 多串口/多设备同屏
- 脚本（Lua/JS）做协议解析与自动应答
- AI 摘要：把一段日志丢给模型，输出"异常时间线 + 可能原因"（Serial Studio Pro 已有类似思路）

### 8.4 技术选型建议

| 方案 | 优点 | 缺点 | 适合 |
| --- | --- | --- | --- |
| **Tauri 2 + Rust + Web 前端** | 安装包小（~10 MB）、性能好、跨平台、前端生态强 | Rust 串口/线程需要功底 | 想长期维护的正式产品 |
| **Qt 6 / QML（C++）** | 串口成熟、性能稳、原生体验 | 开发速度慢、包体较大 | 工业/桌面团队 |
| **Electron（comNG 路线）** | 开发最快、可直接参考 comNG | 包体 100 MB+、内存高 | 快速验证/内部工具 |
| **Python + PySide6** | 原型快、pyserial 成熟 | 打包麻烦、性能一般 | 个人工具/脚本党 |

> 若目标是"最快出成果"，**fork comNG（MIT）加一个 EasyLogger 解析/过滤面板**，比从零写快一个数量级；若目标是"商业产品、完全可控"，建议 Tauri 或 Qt 自研。

### 8.5 许可注意

- 参考/复用 comNG：MIT，保留版权声明即可。
- 复用 COMTool：LGPL-3.0，动态链接/独立进程可闭源，修改核心需开源。
- 复用 SerialTest / Serial Studio 核心：GPL-3.0，衍生产品必须 GPL 开源，**不适合闭源商业配套**。
